# Честно о защите

## Что реально работает

1. **Серверная проверка.** Клиент не хранит ответ «можно работать» локально —
   каждые 12 секунд он спрашивает сервер. Пока сервер отвечает, ключ можно
   отозвать в любой момент.
2. **HWID-привязка.** Ключ привязывается к отпечатку ПК. Передать ключ другу
   можно, но у друга будет `HWID_MISMATCH` до сброса.
3. **HMAC-подпись ответов.** Ответ `{"enabled": true}` нельзя подделать, не зная
   `CLIENT_SECRET`. Подмена DNS/hosts не поможет.
4. **Подпись запросов.** При `CLIENT_SIGN_REQUIRED=1` сервер принимает только
   запросы, подписанные секретом (защита от простого `curl`).
5. **Kill switch.** Один флаг в БД → все клиенты останавливаются.
6. **Сигналы о взломе.** Отладчик/подмена функций → запись в событиях, по
   желанию автобан.
7. **Обфускация.** PyArmor + отсутствие читаемых имён заметно поднимают порог
   входа для «школьника с декомпилятором».

## Что не работает и не может работать

* **`CLIENT_SECRET` можно достать из `.exe`.** Любой секрет внутри клиента
  извлекаем. После извлечения можно эмулировать сервер. Против этого —
  только серверные сигналы (аномалии, много HWID на один ключ) и регулярные
  обновления.
* **Локальную проверку можно вырезать.** Если убрать вызов `verify`, клиент
  просто не будет спрашивать сервер. Ловушка «tamper» поймает только
  небрежную правку (сломанные функции, отладчик, убитый heartbeat); аккуратный
  патч её обойдёт.
* **HWID подделывается** (спуферы, виртуалки). Это всегда гонка вооружений.
* **Anti-tamper не должен вредить.** Всё, что делает клиент, ограничено его
  собственным процессом и файлом. Никаких удалений чужих файлов, реестра,
  автозапуска — иначе это уже малварь, и антивирусы будут правы.

## Почему окна блокировки нейтральные

В `client/guard.py` тексты в `LOCK_TEXTS` — без оскорблений. Причина простая:
задача окон — не дать работать, а не унизить человека. Оскорбления:
* повышают шанс жалобы/репорта и блокировки твоего Discord-сервера;
* ничего не добавляют к защите;
* при разборе инцидента выглядят как травля.

Хочешь жёстче — поменяй строки, код к этому готов. Но лучше направить энергию
в другое: быстрый бан HWID, автобан по сигналу, отзыв ключа.

## Про антивирусы

Самоудаление `.exe`, `--noconsole`, эмуляция кликов, `keyboard`-хуки — всё это
типовые признаки, по которым Defender/ESET/Kaspersky помечают файл. Это
ожидаемо и не лечится кодом. Что помогает:

1. подпись кода (Code Signing Certificate, от ~$100/год) — сильно снижает
   количество срабатываний;
2. отправка файла в Microsoft (https://www.microsoft.com/en-us/wdsi/filesubmission)
   как false positive;
3. прозрачная инструкция пользователю (уже есть в билде);
4. не менять `.exe` после подписи и не пересобирать без нужды.

## Приватность

Клиент отправляет: HWID (хеш), Discord ID (если известен), версию, IP (видит
сервер). Никаких файлов, скриншотов, буфера обмена, списка процессов.
Если планируешь собирать больше — предупреди пользователей, это уже
персональные данные.

## Рекомендации по эксплуатации

* `CLIENT_SECRET` и `ADMIN_API_KEY` — разные, длинные, только в `.env`.
* `.env` не коммитить (см. `.gitignore`).
* Ротация `CLIENT_SECRET` = пересборка всех клиентов. Делай редко.
* Бэкап БД раз в неделю.
* Логи `TAMPER` просматривай: серия событий с одного HWID — повод для бана.
* Не выдавай админку всем подряд: `OWNER_IDS` — только ты.
