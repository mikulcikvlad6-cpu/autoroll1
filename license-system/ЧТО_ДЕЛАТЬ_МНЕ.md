# Что нужно сделать тебе (а что уже сделано)

Ниже — только ручные действия. Всё, что можно было написать кодом, уже написано
и протестировано (12 тестов API + живой e2e-тест клиента).

---

## Этап 1. Discord Developer Portal (15 минут)

1. Открой <https://discord.com/developers/applications> → **New Application**.
   Имя любое, например `AutoRoll`.
2. Слева **OAuth2** → скопируй:
   * **Client ID** → это `DISCORD_CLIENT_ID`
   * **Client Secret** (кнопка Reset Secret) → `DISCORD_CLIENT_SECRET`
3. Там же **Redirects** → **Add Redirect** и добавь **две** строки:
   ```
   http://127.0.0.1:8000/oauth/callback
   https://<адрес-твоего-сервера>/oauth/callback
   ```
   Вторую добавишь, когда узнаешь адрес на Render (шаг 2). Совпадение должно быть
   посимвольное, с `https://` и без слэша на конце.
4. Слева **Bot** → **Add Bot** → **Reset Token** → скопируй токен
   → это `DISCORD_BOT_TOKEN`. Токен показывается один раз.
5. На той же странице **Privileged Gateway Intents** включи:
   * ✅ **Server Members Intent**
   * ✅ **Message Content Intent**
   (Для слэш-команд технически не обязательны, но ты просил — включаем.)
6. **OAuth2 → URL Generator**:
   * Scopes: `bot`, `applications.commands`
   * Bot Permissions: `Send Messages`, `Embed Links`, `Read Message History`
   * Скопируй ссылку внизу и открой её → выбери свой сервер → Authorize.
7. Свой Discord ID: в клиенте **Настройки → Дополнительно → Режим разработчика**,
   затем правая кнопка по себе → **Копировать ID**. Это `OWNER_IDS`.
   (Можно несколько через запятую.)

> Проверка: бот появился на сервере, в списке участников он online после запуска.

## Этап 2. Сервер и база (20 минут)

Выбери один вариант.

### Вариант А — Render (проще, но Postgres бесплатный только 30 дней)

1. Залей папку `autoroll-license` в GitHub-репозиторий.
2. <https://dashboard.render.com> → **New → Blueprint** → выбери репозиторий.
   Render сам прочитает `render.yaml` (сервис + база).
3. Заполни переменные, которые помечены `sync: false`:
   `CLIENT_SECRET`, `ADMIN_API_KEY`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`,
   `DISCORD_BOT_TOKEN`, `OWNER_IDS`, `PUBLIC_BASE_URL`, `DISCORD_REDIRECT_URI`.
   * `CLIENT_SECRET` и `ADMIN_API_KEY` сгенерируй:
     ```powershell
     python -c "import secrets;print(secrets.token_urlsafe(48))"
     ```
     запусти дважды — получишь два разных значения.
   * `PUBLIC_BASE_URL` = `https://autoroll-license.onrender.com` (твой адрес).
   * `DISCORD_REDIRECT_URI` = `PUBLIC_BASE_URL + /oauth/callback`.
4. Дождись деплоя, открой `https://<адрес>/api/v1/health` — должно быть `{"ok":true}`.
5. Вернись в Discord → OAuth2 → Redirects и добавь боевой адрес.
6. Бот: Render free **засыпает** через 15 минут простоя, поэтому бота держи
   отдельно (VPS) или перейди на платный инстанс. Подробности — `docs/DEPLOY.md`.

### Вариант Б — Railway

1. **New Project → Deploy from GitHub** → выбери репозиторий.
2. **+ New → Database → PostgreSQL**.
3. В сервисе приложения: **Variables** → добавь те же переменные, что выше;
   `DATABASE_URL` возьми из вкладки Postgres (`${{Postgres.DATABASE_URL}}`).
4. **Settings → Networking → Generate Domain** → этот домен идёт в
   `PUBLIC_BASE_URL` / `DISCORD_REDIRECT_URI`.

### Вариант В — VPS за $5 (самый стабильный)

```bash
git clone <repo> && cd autoroll-license/server
cp .env.example .env && nano .env     # заполнить
docker build -t autoroll .
docker run -d --restart=always --name autoroll --env-file .env -p 80:8000 autoroll
# бот:
docker run -d --restart=always --name autoroll-bot --env-file .env autoroll python bot/bot.py
```
Плюс домен и HTTPS (Caddy/Nginx). Тогда `PUBLIC_BASE_URL=https://твой.домен`.

## Этап 3. Первый запуск системы

1. Заполни `server/.env` (локально) теми же значениями.
2. Запусти API и бота (см. `README.md` → быстрый старт).
3. В Discord на своём сервере:
   ```
   /getkey            → получишь ключ
   /admin stats       → сводка
   /admin killswitch enabled:false   → красная кнопка
   ```
4. Выдай себе `OWNER_IDS` — иначе админ-команды не сработают (проверь, что ID
   именно твой, а не имя).

## Этап 4. Сборка roll.exe (10 минут)

1. Скопируй в папку `client/`:
   * `button.png` (лежит в `AutoRoll/roll/button.png`)
   * `icon.ico` (лежит в `AutoRoll/icon.ico`)
2. Установи зависимости:
   ```powershell
   cd client
   pip install -r requirements.txt pyinstaller pyarmor
   ```
3. Собери билд под конкретного человека:
   ```powershell
   python build_one.py --discord-id <его_discord_id> --obfuscate
   ```
4. Готовый комплект: `dist\<discord_id>\` — `roll.exe`, `button.png`,
   `Инструкция.txt`, `manifest.json` (SHA-256 и ID сборки).
5. Проверь на «чистой» машине: первый запуск → окно с ключом → ключ из ЛС.

> Если PyArmor не установился — сборка продолжится без обфускации, просто
> напишет предупреждение. Без `--obfuscate` тоже работает.

## Что проверить после настройки (5 минут)

- [ ] `/getkey` выдаёт ключ и присылает его в ЛС.
- [ ] Первый запуск `roll.exe` просит ключ и активируется.
- [ ] Второй запуск не просит ключ (кэш в `%APPDATA%\AutoRoll`).
- [ ] `/admin revoke <ключ>` → клиент в течение ~15 секунд закрывается.
- [ ] `/admin killswitch enabled:false` → клиент закрывается и удаляет `.exe`.
- [ ] `/admin ban <hwid>` → при запуске блокирующие окна.
- [ ] `/admin events` показывает `TAMPER`, если запустить клиент под отладчиком.

## Что я сознательно сделал не так, как в задании

1. **«Кара» без оскорблений.** В `client/guard.py` есть `LOCK_TEXTS` — там
   нейтральные тексты («Доступ заблокирован», «Устройство в чёрном списке»).
   Ты можешь вписать что угодно, но оскорбления в окнах — это лишний повод для
   жалоб и блокировок, а эффект тот же.
2. **Kill switch удаляет только свой `.exe`** и только через `%TEMP%\*.bat`.
   Ничего в системе пользователя не трогается.
3. **OAuth2-ключ выдаётся и на странице, и в ЛС** — если у пользователя закрыты
   ЛС, он всё равно получит ключ.
4. **`CLIENT_SECRET` зашит в `.exe`.** Любую клиентскую защиту можно распаковать;
   лучшая защита — серверная проверка HWID + kill switch. Подробнее в
   `docs/SECURITY.md`.

## Если что-то сломалось

| Симптом | Причина | Что делать |
|---|---|---|
| `/getkey` молчит | бот не запущен / нет токена | смотри логи `bot\bot.py` |
| Команды не появились | не синхронизировались | укажи `DISCORD_GUILD_ID` — синк мгновенный |
| «Нет связи с сервером» | неверный `PUBLIC_BASE_URL` / сервер спит | открой `/api/v1/health` в браузере |
| OAuth: `invalid redirect_uri` | адрес в портале ≠ `DISCORD_REDIRECT_URI` | приведи к одному виду |
| Клиент пишет «ответ не прошёл проверку подписи» | `CLIENT_SECRET` в `.exe` ≠ на сервере | пересобери `.exe` с тем же секретом |
| 401 `UNSIGNED` | на сервере `CLIENT_SIGN_REQUIRED=1`, старый клиент | пересобери клиент |
